## 6. Approved Channels

- **Confirmed Channel**: `HrNotificationChannel.inApp` (In-App Notification).
- **Prohibited / Deferred Channels**:
  - Push Notifications (Firebase Cloud Messaging, OneSignal, APNs) are external backend capabilities and are **not** implemented in client code.
  - Email Notifications (SMTP, SendGrid) are backend responsibilities.
  - SMS notifications are out of scope.

---

## 7. Notification Identity

- **Format**: Stable string identifier (e.g. `'notif_001'`, `'notif_002'`, `'notif_101'`).
- **Generation**: Deterministic monotonic incrementation in mock storage.
- **Invariant**: Stable domain IDs only. Random strings, list indices, and UI row offsets are strictly prohibited as identity keys.

---

## 8. Recipient Identity

- **Contract**: Every notification is explicitly addressed to `recipientUserId` (`CurrentUser.id`, e.g. `'usr_admin'`, `'usr_hr'`).
- **Identity Distinction**: `CurrentUser.id` is distinct from workforce `Employee.id` (`'emp_1'`). Workforce employees do not necessarily hold CRM user credentials; notifications route exclusively to CRM accounts.

---

## 9. Event References

Each notification retains an immutable relationship to its originating source event:
- `requestId`: Foreign key reference to `HrApprovalRequest.id` (e.g. `'appr_req_1'`).
- `target`: `HrApprovalTarget` reference (`targetModule`, `targetEntityType`, `targetEntityId`).

---

## 10. Notification Types

```dart
enum HrNotificationType {
  approvalRequestSubmitted('Approval Request Submitted'),
  approvalDecisionRecorded('Approval Decision Recorded'),
  approvalRequestCancelled('Approval Request Cancelled');
}
```

Zero unapproved notification types (such as salary disbursement alerts or attendance penalty notices) are permitted.

---

## 11. Data Model

The `HrNotification` entity encapsulates:
- `id` (String): Unique identifier.
- `recipientUserId` (String): Authorized recipient user ID.
- `type` (HrNotificationType): Notification category.
- `channel` (HrNotificationChannel): Delivery channel (inApp).
- `title` (String): Concise headline.
- `body` (String): Privacy-safe event description.
- `target` (HrApprovalTarget): Referenced domain entity.
- `requestId` (String): Referenced approval request.
- `createdAt` (DateTime): UTC timestamp.
- `isRead` (bool): Read/unread flag.
- `readAt` (DateTime?): UTC timestamp when marked read.

---

## 12. Content Privacy

**Mandatory Privacy Invariants**:
1. **Zero Financial Amounts**: Basic salary, gross pay, net pay, allowances, and tax deductions must **never** be included in notification titles, bodies, or payloads.
2. **Zero Sensitive PII**: National IDs, home addresses, phone numbers, and bank account numbers are strictly omitted.
3. **Safe Content Examples**:
   - `Title`: `'New Approval Request'`, `Body`: `'A new request for Attendance Record att_101 has been submitted by usr_hr.'`
   - `Title`: `'Approval Decision Recorded'`, `Body`: `'Your request for Payroll Period period_2026_01 was approved.'`

---

## 13. Repository Interface

`HrNotificationRepository` defines:
- `sendNotification(HrNotification notification)`: Persists and sends a notification.
- `getNotificationsForUser(String userId)`: Retrieves user notifications (newest first).
- `getUnreadNotificationsForUser(String userId)`: Retrieves unread user notifications.
- `getUnreadCount(String userId)`: Derives count of unread notifications.
- `getNotificationById(String id, {required String recipientUserId})`: Authorized lookup.
- `markAsRead(String id, {required String recipientUserId})`: Updates read state.
- `markAllAsRead({required String recipientUserId})`: Marks all user items read.
- `clearUserNotifications({required String recipientUserId})`: Session reset.

---

## 14. Mock Implementation

`MockHrNotificationStore` & `MockHrNotificationRepository`:
- Seeded with deterministic records for `usr_admin` (`notif_001`, `notif_003`) and `usr_hr` (`notif_002`).
- Defensive copy isolation: returns clones so mutations outside the repository do not corrupt storage.
- Simulated error testing via `simulateFailure = true`.
- Monotonic ID generation (`notif_101`, `notif_102`, etc.).

---

## 15. Delivery Semantics

- **In-App Immediate**: Stored notifications are immediately available to the authorized recipient upon query.
- **No Speculative Delivery**: An in-memory mock record does not imply background push delivery.
- **State Isolation**: Notification delivery status does not alter approval request status.

---

## 16. Read / Unread Behavior

- Notifications are initialized with `isRead = false` and `readAt = null`.
- `markAsRead` transitions `isRead` to `true` and sets `readAt` to current UTC time.
- Unread count dynamically reflects the number of unread notifications belonging exclusively to the authenticated user.

---

## 17. Ordering

- All queries return notifications ordered chronologically by `createdAt` descending (newest first).

---

## 18. Authorization

- **Scoping**: All repository operations enforce `recipientUserId` checks.
- **Cross-User Protection**: Attempting to read or mark as read a notification belonging to another user throws `HrNotificationException.unauthorizedRecipient`.

---

## 19. Session Isolation

- `HrNotificationCubit` implements `clear()` on logout.
- Switching user sessions clears displayed notifications and resets active user tracking (`_activeUserId`).
- Late asynchronous responses for prior users are discarded via user ID matching.

---

## 20. Error Handling

- Standardized `HrNotificationException` with error codes:
  - `unauthorized_recipient`
  - `notification_not_found`
  - `invalid_read_state_transition`
  - `delivery_failed`
- Safe exception presentation without leaking sensitive payloads.

---
